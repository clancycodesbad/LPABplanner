# BUG-002: Onboarding's automated subject placement discards failure results

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-09-26 · Project: LPABplanner

## Summary

`applyPathway` (`js/ui/ui-onboarding.js:157-165`) and the Path B "confirm" handler (`js/ui/ui-onboarding.js:220-226`) both call `PlannerState.addSubject(termId, subject)` inside a loop and discard the returned `{success, errors}` object entirely. If any placement fails, the student sees no indication anything went wrong — onboarding completes as if every subject were placed successfully.

## Spec reference

No formal spec states this explicitly. The requirement is inferred from the codebase's own established pattern: `ui-board.js`'s `handleAddSubject` (used for every manual drag-and-drop placement) explicitly checks `result.success` and displays an error banner (plus a toast on touch devices) when it's `false`. The two onboarding call sites bypass this established pattern entirely by calling `PlannerState.addSubject` directly instead of going through `handleAddSubject`.

## The code

```js
// ui-onboarding.js:157-165
function applyPathway(terms) {
    SUGGESTED_PATHWAY.forEach((sem, i) => {
        const termId = terms[i];
        sem.subjects.forEach(id => {
            const subject = subjects.find(s => s.id === id);
            if (subject) PlannerState.addSubject(termId, subject); // return value discarded
        });
    });
}
```

```js
// ui-onboarding.js:220-226
overlay.querySelector('#ob-confirm').addEventListener('click', () => {
    ctx.checked.forEach(id => {
        const subject = subjects.find(s => s.id === id);
        if (subject) PlannerState.addSubject('completed', subject); // return value discarded
    });
    finishWizard(overlay, onComplete);
});
```

## Observable consequence

Mechanically verified (Phase 3, Pass 1): the currently-shipped `SUGGESTED_PATHWAY` data never places more than 3 subjects/electiveSlots in any semester (well under the 4-subject cap), so this defect is **not currently triggerable** by Path A with today's data. However, the code itself has zero handling for the failure case — if a future edit to `SUGGESTED_PATHWAY` (a plain hardcoded array with no validation against `engine.js`'s constraints) ever pushed a semester over capacity, or introduced a term-availability mismatch, this defect would immediately become live with no other code changes required. It is best characterized as a dormant defect, not a purely theoretical one.

## The fix

```diff
--- a/js/ui/ui-onboarding.js
+++ b/js/ui/ui-onboarding.js
@@ -155,10 +155,17 @@
 
 function applyPathway(terms) {
+    const failures = [];
     SUGGESTED_PATHWAY.forEach((sem, i) => {
         const termId = terms[i];
         sem.subjects.forEach(id => {
             const subject = subjects.find(s => s.id === id);
-            if (subject) PlannerState.addSubject(termId, subject);
+            if (subject) {
+                const result = PlannerState.addSubject(termId, subject);
+                if (!result.success) failures.push(`${subject.name}: ${result.errors.join(' ')}`);
+            }
         });
     });
+    if (failures.length > 0) {
+        console.warn('[onboarding] Some subjects could not be placed:', failures);
+        // TODO(maintainer): surface `failures` to the student — see BUG-002 writeup for UX options.
+    }
 }
```

**This diff is a proposal, not an applied/validated fix.** The `console.warn` placeholder is intentionally conservative — it stops the failure from being *completely* silent (a developer or future session can find it) without committing to a specific UX (a banner? a toast? a summary screen before "finish"?) that the maintainer should decide. A parallel change is needed for the Path B confirm handler at lines 220-226.

## The test

`quality/test_regression.mjs`'s `BUG-002` test simulates the exact discard pattern used by both call sites and confirms that a failure result produces zero captured signal when the calling code follows this pattern. Run: `node --test --test-name-pattern="BUG-002" quality/test_regression.mjs`. Current output: PASS (confirming the gap — see `quality/results/BUG-002.red.log`).

## Related issues
