# BUG-004: Markdown export sorts semesters alphabetically instead of chronologically

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-09-26 · Project: LPABplanner

## Summary

`handleExport` (`js/ui/ui-toolbar.js:26`) sorts the plan's semester keys with a plain `.sort()` call — lexicographic string ordering — instead of chronological ordering. For plans spanning certain year boundaries, this produces a semester order in the exported markdown that disagrees with real time, and additionally disagrees with the chronological order the app's own board view (`ui-board.js`) renders the same semesters in.

## Spec reference

README.md: "**Markdown export** — One-click copy of the full plan, formatted for Notion, Obsidian, or similar tools." A "full plan" export implies a readable, sensible ordering; the app's own board rendering (chronological) is the natural baseline for what "sensible" means here.

## The code

```js
// ui-toolbar.js:26
Object.keys(plan).filter(k => k !== 'completed').sort().forEach(term => {
    // ...
});
```

`'summer2030'.localeCompare('winter2029')` sorts `'summer2030'` first (lexicographically, `'s' < 'w'`), even though `winter2029` (July/August 2029) precedes `summer2030` (March 2030) in real time.

## Observable consequence

A student with a plan spanning `winter2029` and `summer2030` sees them appear in the app's own board in chronological order (winter2029, then summer2030) but in the *reverse*, alphabetical order in their exported markdown (summer2030, then winter2029) — an internally inconsistent experience within the same tool.
