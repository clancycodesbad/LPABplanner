## Additional independent finding not previously flagged (minority finding — this auditor only)

**A5-1 [NEW, minority] — `js/state/planner-state.js:39-42` (`getClashes`) silently defaults `currentTerm` to `'winter2026'` if the imported value is nullish, independently of `subjects.js`'s actual `currentTerm` export.**

```js
getClashes(semesterId) {
    if (!_plan[semesterId]) return {};
    const safeTerm = currentTerm ?? 'winter2026';
    return Engine.getClashingSubjects(_plan[semesterId], semesterId, safeTerm);
},
```

Cross-referenced against `ui-board.js:19-21`'s `getExamText`, which has the *identical* fallback pattern (`typeof currentTerm !== 'undefined' ? currentTerm : 'winter2026'`). Both fallbacks hardcode `'winter2026'` as the safety net. Given `subjects.js` now computes `currentTerm` dynamically via `computeCurrentTerm()` (confirmed via the mid-run source drift noted in PROGRESS.md), `currentTerm` becoming `undefined`/`null` is only plausible if the import itself fails (a build/bundling error), in which case the whole app would likely already be broken — so this is a low-severity, largely theoretical robustness note, not escalated to a tracked BUG. Recorded here as a minority finding per the audit protocol's requirement to record even single-auditor findings rather than discard them silently. **Triage disposition: not promoted to BUGS.md — the hardcoded fallback value (`'winter2026'`) will itself go stale over time (it's a point-in-time snapshot, just like the pre-drift `currentTerm` literal was), but reaching this code path at all requires an import failure that would likely crash the app earlier. Recommend the maintainer note this as a very-low-priority cleanup rather than a defect.**
