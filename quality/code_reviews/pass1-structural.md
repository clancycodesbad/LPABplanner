## Resource lifecycle / concurrency / DnD parity notes

No resource-lifecycle defects found (no file handles, sockets, or locks in this codebase). `attachTouchHandlers`'s remove-then-add event listener pattern (`ui-touch-dnd.js:175-184`) is correct and idempotent — verified by reading `initTouchDnD`'s call sites (`ui-board.js:149`, `ui-pool.js:49`, both called after every render) and confirming `removeEventListener` always precedes `addEventListener` for the same handler reference.

No true concurrency exists (single-threaded, no workers/promises in the reviewed hot paths) — a rapid double-tap on touch could theoretically fire `onPointerDown` twice before `onPointerUp` clears `dragState`, but `onPointerDown` unconditionally overwrites `dragState` rather than guarding against a pre-existing drag, which is a low-severity, hard-to-trigger edge case (would require a second touch point landing on a *different* draggable element mid-drag) — not escalated to a tracked bug given the challenge-gate's common-sense standard, but noted here for completeness.
